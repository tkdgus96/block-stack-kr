# 연습·성장·협동 기능

## 연습실

두 화면 테마에서 연습실 탭으로 이동한다. 대기실에서만 입장할 수 있으며 대전이 시작되면 연습실이 닫힌다. 연습 입력은 서버 대전에 전송되지 않는다.

- T스핀: 준비된 보드에서 실제 SRS 회전으로 Full T스핀을 성공시킨다.
- 콤보: 연속 두 번 줄을 지운다.
- 상쇄: 대기 공격 4줄을 테트리스로 상쇄한다.
- 40줄: 40줄을 지운 완료 시간으로 개인 최고 기록을 겨룬다.
- 2분 도전: 120초 동안 점수를 겨룬다. 실패·미완료 기록은 최고 기록을 덮어쓰지 않는다.

- 마라톤: 10줄마다 레벨이 오르고 150줄을 지우면 끝난다. 시간이 지나도 레벨은 오르지 않는다. 블록이 넘쳐 끝나도 그때까지의 점수를 기록한다.
- Zen: 레벨이 오르지 않는다. 판이 넘치면 판과 대기 공격을 비우고 이어서 한다. 기록은 남기지 않는다.
- 퍼즐: T스핀 더블·싱글·트리플, 테트리스, 퍼펙트 클리어 판 10개. 주어진 블록을 다 쓰기 전에 목표를 이루면 성공이고, 가장 빠른 시간을 저장한다. 모든 퍼즐은 엔진 테스트에서 실제로 풀리는지 확인한다(`engine/src/puzzles.rs`).

모든 연습 모드에서 블록당 키 입력 수와 키 입력 실수를 보여 준다. 키 입력 실수는 생성 위치에서 놓은 자리까지 필요한 최소 키 수(좌우 끝까지 누르고 있기는 한 번, 바로 내리기 포함)보다 많이 누른 블록 수다. 누르고 있어 반복된 이동은 세지 않고, 보관이나 소프트 드롭을 쓴 블록과 자동 낙하로 고정된 블록은 판정하지 않는다.

연습 최고 기록은 이 브라우저에 저장한다. 키보드와 연습 전용 터치 버튼을 제공한다.

## 결과 분석과 리플레이

참가한 최근 대전에서 서버가 전송한 내 보드 상태를 기록한다. 마지막 15초 범위의 보드 스냅샷과 최대 4096개 기술 이벤트를 보관하며 예측 보드를 녹화하지 않는다. 원래 경기 tick 간격으로 재생한다. 기술 타임라인에서 녹화 구간 내 사건으로 이동할 수 있다. 전체 경기 입력 재시뮬레이션이나 상대 보드 녹화는 제공하지 않는다. 이 브라우저에 마지막 한 경기만 저장하며 새로고침 후에도 확인할 수 있다.

개인 기록에는 최근 20경기 APM 변화도 표시한다. 기존 로컬 최근 50경기와 서버 누적 프로필은 별도로 표시한다.

## 서버 프로필·미션·보상

로그인 절차 없이 무작위 256비트 복구 코드를 생성한다. 서버는 복구 코드의 SHA-256 해시를 파일 이름으로 사용하며 평문 코드를 파일에 저장하지 않는다. 코드를 직접 표시하고 다른 기기에 입력하면 누적 대전 수·공격 줄·승수·미션·해금 테마를 이어받는다. 복구 코드를 아는 사람은 같은 프로필에 접근할 수 있다.

완료된 2인 이상 대전만 서버가 기록한다. 관전·연습·협동전은 제외한다. 같은 복구 코드로 여러 자리에 참가하면 한 경기로 합치며, 공격량은 가장 높은 자리의 값, 승리는 무승부를 제외한 어느 자리의 승리든 반영한다. 브라우저 저장이 차단되어도 현재 탭에서는 코드를 유지하고 직접 표시해 보관할 수 있다. 같은 경기의 중복 집계를 막고 서버 시각 UTC 00:00(한국 오전 9시)에 일일 미션이 바뀐다.

- 하루 3경기 완료
- 하루 공격 20줄
- 하루 1승

미션 누적 1/3/9개에 오션/선셋/바이올렛 테마가 해금된다. 테마 선택은 기기별로 저장한다. 게임 규칙에는 영향을 주지 않는다.

운영 데이터는 `BS_DATA_DIR/profiles`에 원자적으로 저장한다. systemd는 `/var/lib/block-stack`을 영속 상태 디렉터리로 사용한다. 릴리스 교체와 별개로 보관되며 해당 폴더를 백업해야 한다. 기본 개발 폴더 `data/`는 git에서 제외한다.

## 대기실·모바일·몰입감

같은 닉네임도 P번호로 구분한다. 내 이름·나 배지·방장 왕관·준비 상태와 인원 수를 표시한다. 첫 경기부터 다른 사람의 준비가 필요하며 방장의 시작 버튼은 본인의 시작 동의로 취급한다. 경기 중에는 준비 배지 대신 경기/관전/탈락 상태를 표시한다.

선택형 보드 제스처는 설정에서 켠다. 탭 회전, 가로 드래그 이동, 충분히 긴 아래 스와이프 고정을 제공한다. 기존 버튼은 계속 사용할 수 있다. 작은 흔들림·취소·멀티터치는 하드드롭으로 처리하지 않는다.

아케이드에서는 사운드를 켰을 때 콤보 음정 상승·T스핀·테트리스·마지막 30초·큰 대기 공격 알림, 4줄 이상 공격을 받을 때 낮은 경고음이 나온다. 효과음은 파일 없이 Web Audio 합성음으로 만든다. 애니메이션 설정을 켜면 줄을 지울 때 내 게임판 둘레가 빛나고(테트리스·T스핀·퍼펙트 클리어는 노란 빛), 4줄 이상 공격을 받으면 게임판이 짧게 흔들린다. 동작 줄이기 설정에서는 둘 다 나오지 않는다. 배경 변화는 애니메이션 설정을 따르며 업무 화면·고대비·저사양·동작 줄이기 환경을 고려한다. 기본 무음 설정은 유지한다.

## 협동 생존전

대기실에서 방장이 협동 모드를 켠다. 팀전과 동시에 사용할 수 없다. 서로 공격하지 않으며 상쇄 후 남은 공격을 공동 목표 80줄에 합산한다. 제한 시간 내 목표를 달성하면 전원 성공이다. 10초마다 생존자에게 방해줄을 보낸다(2줄부터 시작, 30초마다 증가, 최대 6줄). 한 명이 탈락해도 나머지는 계속 도전한다. 전원 탈락하거나 시간이 끝나면 실패한다. 개인 승률·서버 미션에는 합산하지 않는다.

## 빠른 대전과 레이팅

방 찾기나 대기실의 **빠른 대전 1:1**을 누르면 대기열에 들어간다. 서버는 레이팅 차이가 허용 범위(150점, 기다린 1초마다 25점씩 넓어짐) 안인 사람끼리 비공개 2인 방을 만들고, 두 사람이 들어오면 준비 단계 없이 바로 시작한다. 15초 안에 상대가 없으면 봇과 붙인다. 매칭된 사람이 30초 안에 들어오지 않으면 방을 닫는다.

레이팅은 Glicko-2로 계산하고 서버 프로필에 저장한다. 서로 다른 프로필을 가진 사람 두 명의 1:1 개인전만 반영하고, 봇전·팀전·협동전·같은 프로필끼리의 경기는 반영하지 않는다. 로그인 없이 복구 코드만으로 만드는 프로필이라 새 코드를 만들면 점수를 처음부터 다시 쌓을 수 있다. 그래서 순위표 없이 개인 기록 화면에 참고용으로만 보여 주고, 빠른 대전 상대를 고르는 데 쓴다.

## 전체 경기 리플레이

서버가 경기마다 시드와 tick별 입력·받은 공격·퇴장만 기록하고, 끝나면 `BS_DATA_DIR/replays`에 저장한다(최근 500경기). 개인 기록 화면의 "전체 경기 다시 보기"는 이 기록을 받아 같은 엔진으로 다시 실행해 모든 참가자의 게임판을 보여 준다. "공유 링크 복사"로 만든 `?replay=<id>` 주소를 열면 같은 경기를 볼 수 있다. 서버 테스트에서 5인 경기(봇 3명, 중간 퇴장 1명)를 다시 실행해 모든 게임판과 통계가 서버와 같은지 확인한다. 기존 "마지막 15초" 리플레이와 기술 타임라인은 그대로 둔다.

## 서버 순위표

40줄 스프린트, 2분 점수 도전, 마라톤 기록은 서버 순위표(모드별 상위 20명 표시, 100명 보관)에 올라간다. 클라이언트는 시드와 입력 기록만 보내고, 서버가 처음부터 다시 실행해 나온 기록만 저장한다. 서버 프로필이 있어야 등록할 수 있고 프로필마다 가장 좋은 기록 하나만 남는다. 파일은 `BS_DATA_DIR/leaderboard`에 있다.

## 봇 난이도

- 쉬움: 지금 블록의 회전×열 위치만 평가한다(기존 방식).
- 보통: 보관한 블록과 비교하고, 다음 블록까지 한 수 앞을 본다.
- 어려움: 보통에 더해 엔진 입력으로 바닥에서 밀어 넣기·180도 회전·T스핀 자리를 찾고, 공격량에 가중치를 크게 준다. 릴리스 빌드에서 한 번 판단하는 데 평균 1.6ms, 가장 길게 4.3ms 걸렸다(서버 tick은 16.7ms).
