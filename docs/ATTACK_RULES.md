# 공격·회전·콤보 규칙

이 프로젝트의 결정적 게임 규칙이다. 특정 상용 게임의 전체 Guideline 호환성을 주장하지 않는다. 엔진은 클라이언트 예측과 권위 서버가 공유한다.

## 회전과 T-Spin 판정

- 90도 CW/CCW 회전은 JLSTZ와 I에 각각 전이별 SRS 보정을 적용한다. 좌표는 오른쪽/아래 방향이 +이며, 0/R/2/L 상태를 사용한다. O는 회전 입력으로 형상을 바꾸거나 회전 이력을 만들지 않는다.
- `RotationInfo.kick_index`는 0부터 시작한다. 4는 다섯 번째 SRS 시도다.
- 고정 직전 마지막 성공 동작이 회전이고 T 중심의 대각선 네 모서리 중 세 곳 이상이 막혀 있으면 T-Spin이다. 벽·바닥·보드 밖도 막힌 칸이다.
- T가 향하는 두 앞 모서리가 모두 막히면 Full, 아니면 Mini다. 다섯 번째 SRS 보정 또는 두 줄 이상 삭제는 Full로 승격한다.
- 프로젝트 정책: 성공한 좌우 이동, 소프트 드롭, 중력 낙하, 거리가 양수인 하드 드롭은 회전 이력을 지운다. 실패한 이동/회전, 거리가 0인 하드 드롭은 유지한다. 스폰·성공한 홀드는 이력을 지운다.

## 기본 공격과 점수

| 종류 | 삭제 줄 | 기본 공격 | 기본 점수 |
|---|---:|---:|---:|
| 일반 | 0 / 1 / 2 / 3 / 4 | 0 / 0 / 1 / 2 / 4 | 0 / 100 / 300 / 500 / 800 |
| Full T-Spin | 0 / 1 / 2 / 3 | 0 / 2 / 4 / 6 | 400 / 800 / 1200 / 1600 |
| Mini T-Spin | 0 / 1 | 0 / 0 | 100 / 200 |

Mini 2줄은 Full 2줄로 승격하므로 공격 4, 점수 1200이다. 삭제 없는 회전은 점수만 주고 공격·콤보 공격을 만들지 않는다. 기본 점수에는 `(level + 1)`을 곱한다. 소프트 드롭 칸당 1점, 하드 드롭 칸당 2점은 별도로 유지한다.

## 콤보·B2B·퍼펙트 클리어

- `combo = -1`은 줄 삭제 연결 없음, `0`은 첫 삭제다. 연속으로 줄을 지울 때마다 1씩 증가하고, 줄을 못 지우면 -1로 초기화한다.
- 기존 콤보 공격표를 유지한다. combo 0..11은 `[0,0,1,1,2,2,3,3,4,4,4,5]`, 이후는 5다. 삭제 시 추가 점수는 `50 * max(combo, 0)`이며 기존처럼 레벨 배수를 적용하지 않는다.
- Tetris(4줄) 또는 줄을 지우는 모든 T-Spin(Mini 포함)은 difficult clear다. 첫 difficult clear의 B2B chain은 1이다. 두 번째부터 기본 공격에 1을 더하고 기본 점수를 1.5배로 한다.
- 줄을 못 지운 고정은 B2B를 유지한다. 일반 1~3줄 삭제는 B2B를 0으로 초기화한다. 삭제 없는 T-Spin도 B2B를 유지하지만 보너스를 적용하지 않는다.
- 줄 삭제 후 보드가 완전히 비면 기존 퍼펙트 클리어 공격 +4를 더한다. 별도의 PC 점수 보너스는 없다.
- `generated = 기본 공격 + 콤보 공격 + B2B 공격 + PC 공격`이다. 받은 대기 공격부터 상쇄한 뒤 남은 양이 `attack`이며, `Stats.sent`는 기존처럼 상쇄 후 남은 공격량을 누적하므로 연습처럼 상대가 없을 때도 증가할 수 있다. 화면의 CombatEvent.sent는 실제 대상에게 전달한 양이며 이때 상대가 없으면 0이다.

## 이벤트와 네트워크 호환성

모든 고정은 `Events.locked`와 함께 `cleared`, `spin`, `combo`, `b2b`, `back_to_back`, `perfect_clear`, `generated`, `cancelled`, `attack` 스냅샷을 낸다. `b2b`는 현재 chain 수이고 `back_to_back`은 이번 고정에 보너스가 실제 적용되었는지다. 이벤트 병합은 수량만 합산하고 마지막 고정의 분류·상태 메타데이터를 보존한다.

`Game.combat`은 `serde(skip)` sidecar다. 기존 Game/Postcard 직렬화의 필드 순서·크기는 유지되며, 역직렬화한 combat은 기본값이다. 확장 상태 메시지를 사용하는 수신 측은 예측 입력을 다시 적용하기 전에 서버의 combat sidecar를 복원해야 한다. 레거시 메시지만 받는 클라이언트는 새 공격을 완전히 예측할 수 없으므로 서버 상태 보정을 받는다.
